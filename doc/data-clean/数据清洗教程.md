## 0. 一分钟看懂数据清洗

**数据清洗 = 把"原始数据"变成"能用的数据"。**

原始数据就像刚买回来的菜：有泥、有烂叶子、大小不一。直接下锅能熟，但不好吃、不好看、不好算。清洗就是摘、洗、切、分类，让它达到"能下锅"的标准。

三个核心思想，全程记住：

1. **不编造数据** —— 缺失就是缺失，宁可留空，不瞎填
2. **口径要记录** —— 每个数字怎么来的（单位、汇率、规则）都要写清楚
3. **要可复现** —— 清洗用脚本做，不手工改，随时能重跑

## 2. 标准流程五步

```
探查 → 定规则 → 执行 → 校验 → 交付
```

### 第一步：探查（先看数据长什么样）

不探查就开洗，等于不看菜就切。探查要回答：

- 多少行多少列？（`df.shape`）
- 每列是什么类型？（`df.dtypes`）
- 缺失多严重？（`df.isna().mean()`）
- 有重复吗？（`df.duplicated().sum()`）

本次探查结果（脚本 `scripts/profile_archive.py`）：

```python
import pandas as pd

df = pd.read_csv("applications.csv")
print(df.shape)                    # (239664, 30)
print(df.isna().mean().round(4))   # 缺失率
```

探查结论：
- 命中项目 appid **107 个**，42 个数据集里没有
- 发行日期缺失 **20.6%**，价格缺失 **40%**，币种缺失 43 行
- 价格单位是「分」，币种混杂（USD 50 / CAD 5 / CNY 1 …）
- genres 表是**多语言混排**（同一类型有罗马尼亚语、俄语、日语…20 种语言）

> 探查出的问题，就是后面规则的依据。**探查决定规则，规则决定代码。**

### 第二步：定规则（清洗前写清楚"怎么洗"）

每条规则 = 字段 + 动作 + 缺失怎么办。本次 10 条规则：

| # | 规则 | 动作 | 缺失处理 |
|---|---|---|---|
| 1 | 行级筛选 | 只保留 appid ∈ 项目 149 款 | 未命中直接不要 |
| 2 | 去重 | 按 appid 查重 | 0 重复 |
| 3 | 类型转换 | appid→int，价格→float，is_free→bool | — |
| 4 | 名称 | 去首尾空白 | — |
| 5 | 日期 | 统一 YYYY-MM-DD，提取 year | 无法解析置空 |
| 6 | 价格 | 分→元 → ×当日汇率 → 整数元 | 币种缺失置空 |
| 7 | 折扣 | 校验 0~100 | 越界/缺失置空 |
| 8 | 类型 | genres 关联 + 多语言→中文映射 | 无类型=「未知」 |
| 9 | 好评率 | 数据源无 reviews 表 | 三字段全部置空 |
| 10 | url | 由 appid 拼接 | — |

规则写出来有两大好处：
- **可讨论**：用户确认规则 = 确认清洗口径，避免做完返工
- **可复用**：下次换个数据集，改规则比从头想快得多

### 第三步：执行（写脚本跑，不手工改）

用 Python + pandas 写成脚本，一次跑完。核心操作教学（详见第 4 节），本次脚本逻辑：

```
读 applications.csv（只读用到的列）
  → 过滤出项目 107 款
  → 关联 genres 表拿类型
  → 逐行清洗（日期/价格/类型/缺失）
  → 输出 CSV + JSON
```

### 第四步：校验（用"可能会失败"的方式验证）

清洗完必须验证，验证方式是**独立复算**，不能只看"没报错"。

本次校验（脚本 `scripts/verify_cleaned.py`）：

```python
# 1. 条数核对：CSV 和 JSON 都必须是 107 行
# 2. 字段核对：15 列、顺序与项目一致
# 3. 抽样复算：拿已知样例重新算一遍
rust = next(x for x in cleaned if x["appid"] == 252490)
assert rust["price"] == round(39.99 * 6.705)   # 3999分 USD → 268 元 ✓
# 4. 缺失前后对比：置空策略生效了吗
# 5. CSV / JSON 内容一致性
```

校验结果：107 行、0 重复、Rust 复算 268 元通过、No Man's Sky 复算 161 元通过。

> 凡是"手算一遍能对上"的数字，都值得抽几个验。**复算对不上 = 规则或代码有 bug，必须查。**

### 第五步：交付（数据 + 报告 + 脚本三件套）

| 交付物 | 作用 |
|---|---|
| 清洗后数据（CSV/JSON） | 给项目/分析直接用 |
| 清洗报告 | 记录规则、前后对比、问题清单，可追溯 |

## 3. 六大常见清洗任务（通用知识）

### 3.1 缺失值 —— 最常遇到

三种处理方式，按优先级：

| 方式 | 什么时候用 | 本次用法 |
|---|---|---|
| **置空保留** | 无法可靠补全，让下游决定 | 好评率、缺失价格 |
| 删除整行 | 缺失占比极小且字段关键 | 未命中的 42 款 |
| 填充 | 有明确依据（均值/前后值/0） | 免费游戏价格=0 |

原则：**能置空就不编造**。填一个"猜的"数字比留空更危险，因为它会混进统计结果。

### 3.2 重复值

```python
df.duplicated().sum()          # 查重复行数
df.drop_duplicates("appid")    # 按 appid 去重
```

### 3.3 异常值

先定"合理范围"，再查越界。本次：折扣必须在 0~100，价格为负就是异常。

```python
bad = df[(df["mat_discount_percent"] < 0) | (df["mat_discount_percent"] > 100)]
```

### 3.4 格式统一

- 日期统一 ISO：`pd.to_datetime(x).strftime("%Y-%m-%d")`
- 文本去空白：`str.strip()`
- 大小写统一：`str.lower()`

### 3.5 类型转换

```python
df["appid"] = df["appid"].astype("int64")
df["price"] = df["price"].astype(float)
```

### 3.6 关联与规范化

- **多表关联**：`application_genres.csv`（appid↔genre_id）→ `genres.csv`（id→名称）
- **单位换算**：分 → 元（÷100）→ ×汇率（本次 USD 6.705）→ 整数元
- **多语言规范化**：同一类型 20 种语言 → 映射成中文词表（Action/Acțiune/アクション/動作… → 「动作」）

```python
GENRE_MAP = {
    "Action": "动作", "Acțiune": "动作", "アクション": "动作", "動作": "动作",
    "Adventure": "冒险", "Eventyr": "冒险", ...
}
df["type"] = df["genres"].map(lambda g: GENRE_MAP.get(g, g))  # 未映射的保留原名
```

### 4.3 一个完整的迷你清洗示例

```python
import pandas as pd

# 原始数据：3 行脏数据
raw = pd.DataFrame({
    "id": [1, 2, 2, 3],
    "name": [" 游戏A ", "游戏B", "游戏B", None],
    "price_cents": [990, None, 5000, 3000],
    "release_date": ["2020-01-05", "2019-03-02", "bad-date", "2018-07-11"],
})

clean = (
    raw.drop_duplicates("id")                    # 去重（id=2 留第一行）
       .dropna(subset=["name"])                   # 名字缺失的删除
       .assign(price=lambda d: d["price_cents"] / 100)   # 分 → 元
       .assign(year=lambda d: pd.to_datetime(d["release_date"], errors="coerce").dt.year)  # 提取年份，坏日期→NaN
       .drop(columns=["price_cents"])
       .sort_values("id")
)
print(clean)
```

输出：

```
   id   name release_date  price  year
0   1   游戏A    2020-01-05    9.9  2020
1   2    游戏B   2019-03-02    NaN  2019
```

看懂了这 4 行，pandas 清洗就算入门了：id=2 的重复行被去重（保留第一行）、id=3 因 name 缺失被删、分转成了元、坏日期变成 NaN、id=3 的 price_cents=3000 也随行一起没了（删除行 = 整行消失）。

## 5. 常见坑（血泪清单）

| 坑 | 后果 | 解法 |
|---|---|---|
| 不知道单位就换算 | 价格差 100 倍 | 先查字段说明/已知样例验证（3999 分=39.99 美元） |
| Excel 打开乱码 | 看着像坏了 | 输出用 `encoding="utf-8-sig"` |
| 手工改数据 | 无法复现、说不清改了啥 | 全用脚本，跑完留档 |
| 只看"没报错"就交付 | 数字可能是错的 | 独立复算 + 条数核对 |
| 缺失值乱填 | 统计结果被污染 | 能置空就不编造 |
| 全表清洗 | 又慢又占空间 | 先 `usecols` 选列 + 按需过滤行 |
| 汇率/口径不记录 | 三个月后看不懂数据 | 写进报告 |
